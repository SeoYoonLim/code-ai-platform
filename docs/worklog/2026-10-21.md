## 오늘 찾아낸 중요한 문제들

테스트가 통과했는데도 **실제로 실행하거나 의심해서 찾은** 결함들이다. 이 목록이 오늘의 가장 큰 수확이다.

| # | 결함 | 어떻게 발견했나 | 영향 |
|---|---|---|---|
| 1 | Unsloth가 **비인과적(non-causal) attention**으로 학습 (xformers가 CUDA 12.4용 wheel이라 cu126에서 비활성화) | 어댑터가 카나리아를 못 배움 → 마지막 토큰만 바꿔 앞 위치 logits 변화 측정(9.78 → 0.00000) | 학습 결과 전부 무효. `check_causal.py`를 이미지 건전성 검사로 추가 |
| 2 | `entrypoint.sh`가 **CRLF**라 컨테이너가 즉시 종료 (`set: Illegal option -`) | Docker가 없는 Codex 샌드박스는 못 보는 문제 → 실제 기동 | `.gitattributes`에 `*.sh text eol=lf` |
| 3 | `stream()`이 `yield`를 감싼 `asyncio.timeout` 때문에 **느린 소비자에서 `CancelledError` + `in_flight` 영구 누수** | 코드 읽기 → 실서버에서 재현 | 누수되면 임베딩이 영원히 CPU에 고착(20배 느림). 수정 후 `docker pause`로 서버를 진짜 멈춰도 검증 |
| 4 | 가짜 클라이언트가 이벤트 루프에 **양보하지 않아** 테스트의 `wait_for` 상한이 작동 불가 → 버그 시 CI 60초 매달림 | 변이 시험 중 우연히 | 양보 지점 추가. 7초 만에 실패 |
| 5 | 보고서·ADR에 **무효한 측정값 인용** (버그 있던 이미지의 7B 수치), 서빙 VRAM **MiB를 GB로 오기** | 낮은 모델 버전으로 진행한 구간을 재검증 | 판정은 안 바뀌었으나 문서 정정 |
| 6 | Ollama 별칭으로 장치를 나눌 수 있다는 판단이 **통제되지 않은 실험**의 결론 | 직전에 CPU 러너가 떠 있었음을 뒤늦게 의심 | 깨끗한 상태로 재시험, 카드 정정 |
| 7 | `num_gpu` 생략 시 임베딩이 **CPU에 고착** | 실험에서 처리량이 기대와 다름 | 모든 요청에 `num_gpu` 명시 |
| 8 | `--lora-init-without-apply`가 **도움말과 달리 어댑터를 꺼 두지 않음** (요청에 `lora` 필드가 없으면 어댑터가 몰래 적용) | 필드 없이 보낸 요청에서 카나리아 10/10 | 모든 요청에 전체 어댑터 스케일을 명시 |
| 9 | 첫 변이 시험이 **무효**였음 (하니스가 Git Bash `/tmp`를 못 읽어 변이가 한 번도 적용 안 됨) | 전부 "passed"인 게 이상해서 | "변이가 실제 적용됐는지"를 검증하는 하니스로 재작성 |
| 10 | `docker compose down <서비스>`가 공유 네트워크를 지워 다른 컨테이너가 기동 불가 | `network not found` | 이후 `stop`만 사용 |

## 오늘 확립된 작업 방식

1. **Claude는 설계·카드·리뷰, Codex는 구현.** 인터페이스(`core/interfaces`)는 Claude만 수정. Codex는 `.git`에 쓸 수 없어(샌드박스) **Claude가 리뷰 후 커밋**한다.
2. **카드를 쓰기 전에 실측한다.** T-104 카드는 진짜 Chroma 서버로 11가지 동작을 먼저 확인했고, 내 가정 상당수(이름 길이 제한, `None` 메타데이터 오류, 영벡터 NaN)가 틀렸음이 드러났다.
3. **Codex 결과를 믿지 않고 독립 검증한다.** 같은 검사를 다시 돌리고, 코드를 읽고, **변이 테스트**(버그를 일부러 심어 테스트가 잡는지)로 테스트의 검출력을 시험한다. 정확한 개수는 각 카드의 "리뷰" 절에 있다 (예: T-101은 스위트 3개에 22개 + 동시성 보강분, T-103은 15개, T-104는 29개). 처음에 놓친 변이가 카드마다 있었고(재정렬 생략, `idle_grace` 무시, 동시성 플래그 등) 모두 테스트를 보강해 잡았다.
4. **Docker·GPU가 필요한 검증은 Claude가 한다.** Codex는 구현 + 단위 테스트 + 정적 검증까지, 실행하지 못한 항목은 "미실행 (Claude가 실행)"로 정직하게 분리한다.
5. **적합성 스위트 상속.** Fake가 통과한 규칙을 실제 어댑터가 같은 스위트로 상속해 검증하고, 가짜가 진짜와 같은지는 같은 스위트를 진짜 서버에 돌려 보증한다.

(`AGENTS.md` 완료 조건에 "새로 쓴 스크립트는 실제로 실행한다", "외부 도구의 동작을 가정하지 않는다"를 반영했다.)

## 알려진 위험·한계

- **어댑터가 실제 분석·리팩터링 품질을 올리는지는 한 번도 측정하지 않았다.** 카나리아는 "고정 문자열로 시작한다"는 쉬운 행동이라 로딩·전환·격리가 기계적으로 동작함을 보일 뿐이다. 첫 품질 측정은 M2(base 기준선)와 M6(평가 게이트).
- 3B는 7B보다 품질이 낮다. M2에서 3B base 기준선을 처음 잰다.
- 전체 `chromadb`와 `chromadb-client`는 한 환경에 공존 불가 → Chroma 단위 테스트는 가짜 클라이언트에 의존한다. Chroma를 업그레이드할 때마다 "가짜 vs 진짜 서버" 시나리오 비교를 다시 돌려야 한다.
- 동점 순서는 서버 재시작 사이에 달라질 수 있다 (복붙된 코드의 임베딩이 동일). `RagService`가 `chunk_id`로 동점을 끊어야 한다.
- `mypy --strict`를 테스트까지 돌리면 기존 파일에 14건이 나온다 (CI는 `src`만 검사해 통과). 타입 스텁·pydantic 플러그인 문제가 대부분이나 실제 부정확 3건이 섞여 있다 (T-102 카드 참조).
- `main` 브랜치 보호 규칙은 아직 설정되지 않았다 (GitHub 설정에서 `python`, `contracts`를 필수 체크로 지정할 것).
